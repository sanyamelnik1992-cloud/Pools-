# LP-пулы Arbitrum и Base: доходность и риски

Сбор и анализ данных по LP-пулам DeFi на Arbitrum и Base по данным [Krystal](https://defi.krystal.app/pools),
с перекрёстной проверкой через DefiLlama, GeckoTerminal, DexScreener и RPC сетей. Blast добавлен для сравнения
(Krystal его не поддерживает).

## Запуск

```bash
pip install -r requirements.txt
export KRYSTAL_CLOUD_KEY=...       # ключ Krystal Cloud API (заголовок KC-APIKey)
./run_all.sh                       # или по шагам:
python3 collect.py [--fresh] [--max-history 220] [--days 90]
python3 analyze.py
python3 build_report.py
```

HTTP-ответы кэшируются в `data/.cache/` на 6 часов; `--fresh` игнорирует кэш.

## Что делают скрипты

| Файл | Назначение |
|---|---|
| `collect.py` | Krystal: все пулы с TVL ≥ $10k по каждому протоколу (с incentives и ценами токенов), почасовая история за 90 дней, тики ликвидности. DefiLlama: yields, объёмы/комиссии DEX по сетям, история APY. GeckoTerminal/DexScreener: TVL и объём для сверки, топ пулов Blast. RPC: `liquidity()`, `stakedLiquidity()` (Aerodrome), балансы токенов на контрактах пулов. |
| `analyze.py` | Очистка TVL от накрученных цен, fee APR (24ч/7д/30д/устойчивая), эмиссия (Aerodrome, с учётом доли стейка), волатильность σ, IL-порог σ²/8, коэффициент R = fee APR полного диапазона ÷ σ²/8, риск-балл 1–10, красные флаги, агрегаты по DEX и типам пар, бэктесты диапазонов (пассивно / авто-ребаланс Krystal / стейк AERO) на окнах 90 и 30 дней. |
| `build_report.py` | HTML-отчёт с таблицами и графиками → `report/index.html`. |
| `strategies.py` | Пулы, где оба токена — стейбл/ETH/BTC: бэктест на трёх независимых 30-дневных окнах (позиция открывается заново в начале окна) — какие настройки перекрывают холд во всех окнах; дельта-нейтральная LP (шорт перпа на Hyperliquid с реальным почасовым funding); базис-трейд; ориентиры lending/стейкинга/займов (DefiLlama). |
| `my_position.py` | Разбор LP-позиций кошелька: состав, комиссии, PnL, текущая fee APR по доле в активной ликвидности, сценарии по цене, альтернативы пересборки с бэктестом; нативный баланс по RPC. Пример: `python3 my_position.py --wallet 0x...` (результат — в `data/private/`, не коммитится). С `--invested 50000` считает, при какой цене ETH кошелёк выходит в ноль, и прогноз плана «ETH в стейкинг + комиссии LP в ETH». |
| `v4_analysis.py` | Uniswap v4 и PancakeSwap Infinity против v3 на парах ETH/BTC/стейблы во всех сетях Krystal: где есть v4 (TVL и объём по сетям, DefiLlama), доля комиссии, которая достаётся LP после протокольной комиссии, наличие хука, доход на единицу ликвидности, бэктест на трёх окнах и прямое сравнение — сколько дала бы позиция ETH/стейбл с заданными границами в каждом пуле (`--range 2000 3000`). |
| `hooks_analysis.py` | Инвентаризация хуков Uniswap v4 и PancakeSwap Infinity во всех сетях Krystal: название контракта (Blockscout), права хука из битов адреса и флаги риска (хук может менять суммы свопа или вывода, блокировать вывод), TVL, объём и комиссии; для пар ETH/BTC/стейблы — доход позиции в хуковом пуле против такой же пары без хука. |
| `portfolio_review.py` | Разбор портфеля монет из CSV (`ticker,invested,qty`, пример — `portfolio.example.csv`): стоимость, результат, во сколько раз монета должна вырасти до безубыточности, динамика за 30/90/365 дней, доступный стейкинг, цена ETH для выхода в ноль. Пример: `python3 portfolio_review.py --csv data/private/portfolio.csv`. |
| `sui_pools.py` | Пулы SUI/USDC в сети Sui (Bluefin, Cetus, Turbos, Momentum; Krystal Sui не поддерживает): реальный доход на единицу ликвидности по счётчикам пула `fee_growth_global` и наград за 90 дней (история объектов — Sui GraphQL), коэффициент R, концентрация ликвидности рынка, витринный APR на TVL (GeckoTerminal) и бэктест диапазонов на трёх 30-дневных окнах против холда 50/50, 100% SUI и USDC. Мгновенная активная ликвидность на Sui не используется: боты меняют её в сотни раз за минуты. С `--narrow` — узкие диапазоны (±2…30%) на часовых ценах с пересборкой при выходе цены и без неё против холда SUI (`--usd 4000`, по умолчанию 150 дней); `--range LOW HIGH` — свой диапазон на скользящих 30-дневных окнах (без пересборки, пересборка сразу и через сутки) против холда SUI и «продать ту же долю и держать». |
| `lpscan/` | Общие модули: HTTP с ретраями и кэшем, классификация токенов, очистка, метрики и математика CL. |

## Бот-ребалансер SUI/USDC на Cetus (`bot.py`, `suibot/`)

Бумажный и тестовый режимы: ключи и деньги не нужны. Несколько стратегий ведутся параллельно на одних и тех же
данных пула и сравниваются с «холдом SUI» и с «обменять ту же долю SUI на USDC и держать» (вклад самого пула).

```bash
python3 bot.py backtest --days 365 --minutes 5  # тестовый режим: стратегии из suibot.toml на истории
python3 bot.py scenario --multiple 2 --days 60  # сценарий: SUI ×2 за 60 дней, 100 путей из реальной истории
python3 bot.py paper                            # бумажный режим: виртуальные позиции на живых данных
python3 bot.py report                           # отчёт по бумажным позициям
python3 tests/test_suibot.py                    # проверки математики и учёта (без сети)
```

- Нужен Python 3.11+ и `requests`. Стратегии, пулы и издержки (обмен, проскальзывание, газ) — в `suibot.toml`.
- Бумажный режим каждые `poll_seconds` читает объект пула через Sui GraphQL и начисляет комиссии и награды по
  приросту счётчиков пула, пока цена в диапазоне стратегии; пересборка — по правилам стратегии с издержками.
  Состояние и журналы — `data/private/bot/` (`state.json`, `events.csv`, `snapshots.csv`), бота можно
  останавливать и запускать снова.
- Главная метрика — SUI-эквивалент: стоимость позиции в штуках SUI по текущей цене против «держать SUI» и
  «стейкинг SUI» (`staking_apy`); в долларах — против «обменять ту же долю на USDC и держать».
- Тестовый режим — те же стратегии и учёт на 5-минутных свечах SUIUSDT из открытого архива Binance (полная
  история; `--source gecko` — свечи пула, ~6 месяцев) и фактическом дневном доходе единицы ликвидности пула.
  На часовых свечах узкие диапазоны выглядят лучше, чем есть.
- Правило накопления (`rally_exit`, `resume_drop_pct`): на боковике и падении бот пересобирает пул, на сильном
  росте (например, +15% от минимума за 72 часа) выходит в 100% SUI и ждёт отката от пика, чтобы вернуться.
- Сценарии — цена меняется в `--multiple` раз за `--days` дней: пути собираются из случайных кусков реальной
  5-минутной истории (`--block-days`, вместе с доходом пула за те же свечи) с наклоном до заданного итога.
- Уведомления в Telegram о пересборках и ежедневный отчёт — если заданы `TG_TOKEN` и `TG_CHAT`.

### Боевой режим (`python3 bot.py live`)

Одна стратегия из `suibot.toml` (`[live] strategy`) на реальном кошельке. Решения — те же правила, что в бумажном
режиме и на истории; транзакции строит и отправляет `executor/cli.mjs` на официальных SDK Cetus (закрыть позицию с
комиссиями и наградами → обменять через агрегатор Cetus до нужной доли → открыть новую позицию). Перед каждой
реальной транзакцией — симуляция в сети; при любой ошибке бот встаёт на паузу и пишет в Telegram. Бот берёт из
кошелька не больше `max_capital_usd`, оставляет `gas_reserve_sui` на газ и дальше ведёт свой баланс по фактическим
изменениям балансов из каждой транзакции, поэтому остальные деньги кошелька не трогает.

Запуск на Mac (нужны Python 3.11+ и Node.js 22+):

1. Создайте **отдельный** кошелёк (новый аккаунт в Slush) и переведите на него небольшую сумму SUI и 1–2 SUI на газ.
2. `cd executor && npm install && cd ..` — установить SDK Cetus.
3. Проверка без риска: в `suibot.toml` оставьте `dry_run = true`, впишите `address = "0x…"` своего нового кошелька и
   запустите `python3 bot.py live`. Бот откроет виртуальную позицию и проверит симуляцией, что открытие из вашего
   кошелька проходит.
4. Реальные деньги: `dry_run = false`, ключ (экспорт из кошелька, строка `suiprivkey1…`) — только в переменной
   окружения: `read -s SUI_PRIVATE_KEY && export SUI_PRIVATE_KEY` (ввод скрыт и не попадает в историю), затем
   `caffeinate -i python3 bot.py live`. Ключ никуда не записывайте и никому не отправляйте.
5. Управление: в Telegram (`TG_TOKEN`, `TG_CHAT`) — `/status`, `/pause`, `/resume`, `/sui` (снять позицию и всё в SUI),
   `/usdc` (всё в USDC), `/close` (снять позицию); или из другого окна `python3 bot.py control <команда>`.
   После `/sui`, `/usdc`, `/close` бот на паузе до `/resume`. Остановка (Ctrl+C) не закрывает позицию — она
   продолжает работать в пуле, а бот при следующем запуске продолжит с того же места.

Проверки: `python3 tests/test_suibot.py` и `python3 tests/test_live.py` (боевой цикл с поддельным исполнителем:
старт с лимитом капитала, пересборка, выход в SUI, возврат, ручные команды, учёт своих денег, пауза при ошибке).

## Выходные данные

- `data/processed/pools.csv` — все пулы с метриками и флагами.
- `data/processed/backtests.csv` — результаты бэктестов по ширине диапазона и режиму.
- `data/processed/hold_beaters.csv` — устойчивость к холду по трём окнам (`strategies.py`).
- `data/processed/hedged_lp.csv` — дельта-нейтральная LP с хеджем на Hyperliquid.
- `data/processed/sui_pools.json` — пулы SUI/USDC: доход на единицу ликвидности по дням, R, бэктесты (`sui_pools.py`).
- `data/processed/sui_narrow.json` — узкие диапазоны SUI/USDC с пересборкой против холда (`sui_pools.py --narrow`).
- `data/processed/report_data.json` — всё для отчёта.
- `data/raw/` — снапшоты API (крупная почасовая история и тики в git не хранятся, восстанавливаются `collect.py`).

## Ключевые допущения

- σ — по суточным лог-доходностям цены пула; IL-порог σ²/8 — ожидаемая годовая потеря полнодиапазонной позиции к холду (LVR).
- R вычисляется из активной ликвидности на момент среза (тики Krystal) и комиссий за 7 дней.
- Бэктест: позиция $10 000, доля в комиссиях = доля в активной ликвидности, ликвидность пула масштабируется с TVL;
  авто-ребаланс при выходе из диапазона с тарифом Krystal (0.01/0.03/0.05% от позиции, docs.krystal.app/ecosystem/fees),
  свопом половины позиции по комиссии пула + 0.02% проскальзывания и $0.10 газа; эмиссия AERO постоянна в $/день.
- Это аналитика, а не инвестиционная рекомендация.
